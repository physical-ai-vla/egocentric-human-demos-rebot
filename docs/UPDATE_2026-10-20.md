# HandUMI update, 2026-10-12 → 2026-10-20

[한국어](UPDATE_2026-10-20_ko.md)

This note covers what changed in the HandUMI work after the v5 technical report (2026-10-12). The report itself is
unchanged; nothing here has been added to it yet. HandUMI remains **BrikHMP18's design**
([murobotics-ai/handumi-hw](https://github.com/murobotics-ai/handumi-hw)), not ours; see the README.

The task moved from cube stacking to **T-shirt flattening ("Flatten and align the T-shirt.")** for the laundry project.
Everything below is offline data work or bench/teleop testing. **No policy trained on this data has been evaluated on
the robot, and no UMI→robot replay has been run yet.**

## 2. Gripper open/close from the wrist video

With the servos gone, 74 of the 85 usable UMIalign takes have no `/gripper` topic. The jaw opening is measured from
the red tape in the wrist-camera video instead. No learned model is involved in the dataset labels.

Pipeline:

1. `pipeline/umi_laundry/umi_fusion_scripts/jaw_redx.py` — red mask = `R − max(G,B) > 35` and `R > 90` (a hue gate missed
   the thin, compressed X strokes). Closed jaws merge the two tapes into one blob, so the red pixels are split at the
   image centre column and the opening is the distance between the left-half and right-half centroids
   (px at 1920 width). Against the servo on the overlap takes: corr 0.93, open/closed agreement 97.8 %.
2. `jaw_track.py` (v2) → `<episode>/derived/jaw/jaw_{side}.npz`, one value per wrist frame. Each component is split
   at the centre; a per-side reference (tip height, tape area) is taken from clean frames; candidates must lie in a loose
   height band (±320 px) and area range; temporal continuity picks among several. `--reselect` re-runs selection
   without decoding video. All 154 sides of a run take ~6 min on 7 Mac processes.
3. `cart20/ego_cart20/sources/jaw_visual.py` — binary label: pooled histograms (188k frames) are bimodal,
   closed 110–150 px, open 280–450 px. Hysteresis **closed ≤ 200 px / open ≥ 260 px**, > 650 px = outlier (NaN), NaN gaps
   ≤ 0.5 s filled from neighbours, longer gaps kept but marked invalid. 1 = open.
4. `sources/hfold_export.py` uses the servo when an episode has servo samples (direction read from that episode's
   gripper calibration) and the visual source otherwise; it writes `{side}_gripper_valid`.

Checks: median valid fraction 1.0, open 18–21 % of frames, ~11 transitions per side, 16/16 random frames correct.
The 10-15 fix (candidates ≥ 0.5·a_ref beat small specks) changed 1.28 % of frames, all closed→open, 12/12 verified.
Low-valid sides (< 0.95): 144936 ep2/7/9/10 L (~0.75, X-mark era), 160900 ep08 R 0.79, 112920 ep13 L 0.77.

Traps found: the other unit's tape enters the view ~430 px above the tips; desk specks pass the size test for the small X
marks; with one tape hidden, v1 averaged specks on the empty half; **the wrist camera is not rigid to the jaws** (tips at
y = 437 and y = 635 within one take), so no tight band or arc fit can be used.

Teleop variant (not used for labels): the live teleop read the same tape first with the pixel rule, then with a
fine-tuned ResNet18 classifier on a masked jaw ROI (`experimental/visual_teleop/tools/jaw_capture.py`, `jaw_finetune.py`;
live accuracy 0.96 / 0.92 after a camera-mount change). The `.pt` weights are not in the repo.

## 3. UMIalign collection

- Collector modes `--dataset UMIpilot|UMI100|UMIalign`; UMIalign = Stage 1 of folding on its own, prompt "Flatten and align the T-shirt.", 60 s AUTO window with finish-early (`collection/configs/handumi/tasks.yaml`).
- AUTO loop additions: finish-early event, short voice cues, `device_status.json` every 2 s, `session_log.txt`.
- **End trim:** the operator's reach for SPACE at the end is cut non-destructively via `<episode>/trim.json` +
  `trim_manifest.json` (`space_trim_points.py`, gyro-profile onset − 0.25 s, removes 1.2–3.3 s). Honoured by
  `hfold_export` and the smoother.
- **Raw QA:** `raw_qa.py` (empty takes, red-X presence), `detect_wrist_flip.py` (wrist camera rotated, jaws absent).
  Excluded episodes carry `exclude_from_training` in `episode_meta` and `<session>/excluded_episodes.json`.
- Sessions used for training: `UMIalign_20261013_160900` (30), `20261014_112920` (33), `20261015_112743` (50 kept;
  46 after excluding eps 3/13/18/41). Fold takes (UMIpilot/UMI100) are **not** used.
- Orbbec depth stalls (4–10 s) while the IMUs streamed were a Mac USB-stack state problem, fixed by a reboot
  (`collection/tools/orbbec_{alone,combo}_test.py`).

## 4. Pose pipeline (wrist TCP in a world frame)

`pipeline/umi_laundry/` and `cart20/ego_cart20/umi_fusion/`.

1. **MASt3R-SLAM restart_v1** (`umi_fusion_scripts/m3_runner/run_perframe_restart.py`): restarts after 15 RELOC frames.
   Valid fraction 11–36 % → 87–99 %. It leaks ~3 GB VRAM per side, so one fresh process per tag. Session MASt3R also ran
   on rented 4090s (Vast.ai, RunPod); results were md5-verified onto company storage (5090 NFS, portable SSD).
   The cloud bundle scripts are not in the repo (host addresses, account specifics).
2. **Orbbec body tracking** (`orbbec_tracking/handumi_body_track.py --profile laundry_v1`, height above the table) and the
   canonical tracker (`handumi_canonical_track.py`, params frozen). Held-out recall 0.70–0.73.
3. **Smoother** (`ego_cart20/umi_fusion/run_smoother.py`): Orbbec position anchor + IMU gravity/gyro + MASt3R short-horizon
   motion. Needed because MASt3R drifts in seconds (Sim3 residual p50 69 mm per segment vs 9 mm with 2 s windows;
   tilt error up to 24° at 20 s).
4. **Root cause of bad TCP labels (10-15), found with an absolute check against the jaw tape seen in the Orbbec**
   (`orbbec_tag_check.py`), invisible to the smoother's own QA:
   - stale camera↔IMU rotation: right off 17.5°, left 23.7° → `camera_imu_Rcb_data_v003`;
   - the free camera→body lever converged 20–35 cm off the unit → fixed prior from the jaw-tape tips
     (`tips_v001`, σ = 1e-4);
   - dark-sleeve takeover of the Orbbec anchor → AprilTag gate (`orbbec_tag_gate.py`, drop anchors > 120 mm from the tag).
   Flags: `--rcb data_v003 --rc-prior tips_v001 --sigma-rc 0.0001 --tag-gate` → `derived/umi_fusion_rcb3gate`.
   TCP↔jaw-tape p50: 25–36 cm before → 38–59 mm per session after; p90 is still 15–30 cm.
5. Strict exclusion (ep-side median > 80 mm, gate > 30 %, < 10 samples) → **65 episodes** (160900 27 + 112920 17 +
   112743 21) = dataset `umi_unfold65c922flange_rcb3` (train 56 eps / val 9).
6. Metric tables per session: `drivers/umialign_metrics.py --session <dir>`.

Training status: the 63/109-episode fine-tunes were trained on the pre-fix poses and are baselines only. The corrected
65-episode fine-tune (Multi-Task DiT from the Soft-Fold pretrain 300k) was **stopped by the user at ~11k steps on 10-16**;
there is no result from it.

## 5. UMI → robot: robotization, TCP calibration, replay parity

**Robotization** (`cart20/ego_cart20/robotize/`): human TCP trajectories → reBot base frame. Task frame on the
table between the start TCPs; modes A/B and C (one IK line-search alpha for both arms, HOLD when infeasible); checks IK
residual, joint limits, table, workspace, bimanual distance and joint step. First numbers on 10 training episodes
(mode C, time scale 2): IK-ok p50 0.79, amplitude ratio ~0.81, L↔R relative error p50 ~50 mm. Dataset not built.

**Lead decision 10-16:** stereo cameras dropped; the goal is that UMI-collected motion replays the same on the reBot.

**UMI TCP calibration (done 10-20)** (`pipeline/umi_robot_parity/`): fixed global Orbbec + the 3-tag rigs.
Multi-corner rig PnP (all visible tag corners, SQPNP + LM) cut still rotation jitter 1.78° → 0.39°. The TCP is fitted by
**touching board corners** (`tag_rig_touch_tcp.py`, 50 mm AprilGrid id 300–311, settled-window holds) rather than a
pivot (pivot was ~3 cm off on the left unit). Result in `configs/umi_tag_rig_v001.json` (`tcp_in_rig_m`): right
(10.12, 5.54, −4.29) cm, left (−11.17, 5.67, −4.56) cm; static absolute error 1–4 mm, leave-one-corner-out 1.8–4.8 mm.
IMU↔rig rotation by hand-eye on relative rotations: left rotz(−89.5°) +10 ms, right rotz(+89.8°) +15 ms. IMU fusion
adds nothing for static holds.

**Replay parity tools (built, not run on the robot; the robot was not installed):** `robot_cam_poses.py` (32 poses around
READY, dry-run by default), `robot_cam_solve.py` (T_base_cam + T_flange_tag, reprojection + depth residual, k-fold;
synthetic PASS), `umi_tcp_traj.py`, `umi_replay.py`, `replay_parity.py` (A = UMI measured, B = robot commanded,
C = robot executed on normalized path progress; gates: amplitude ratio 0.9–1.1, leak < 10 %, endpoint < 20 mm,
RMSE < 20 mm, p95 < 30 mm, repeat std < 10 mm). UMI-only 6-direction takes from 10-20 are usable; humans moved 20–35 cm
per stroke, so long strokes may be rejected by the replay limits.

**Kalibr** (`pipeline/umi_robot_parity/kalibr/run_kalibr.sh`): one command, ROS1 bag export → Kalibr docker on the 4090.
The printed AprilGrid needs `patch_kalibr.py` (1-bit border, tags rotated 180°); without it residuals are ~70 px, with it
0.5 px.

## 6. UMI as a teleop device (experimental, negative results kept)

`experimental/visual_teleop/` + `experimental/scripts/umi_teleop_eval/`. Wrist pose sources tried for live teleop:

| source | result |
|---|---|
| DPVO on the wrist camera | NO-GO: rotation drift 40–80° by 30 s, scale wanders 0.03–1.25 (white table + cloth fill the view) |
| mono VIO (OpenVINS / Basalt / ORB-SLAM3) on a room-facing fisheye | NO-GO (jitter p90 76–82 mm, fake translation 27–92 cm) |
| stereo VIO (2 fisheyes + XIAO) | first real-robot teleop 10-16 (81 s at 30 Hz, 0 IK rejects, gripper followed the tape), but board-GT ATE 18.5 cm and the camera bracket slipped; dropped 10-16 |
| fixed Orbbec + tags + IMU | the path kept for data (Sec. 5) |

Lesson: the tracking camera must see a static, textured scene; the wrist view during cloth manipulation does not.
