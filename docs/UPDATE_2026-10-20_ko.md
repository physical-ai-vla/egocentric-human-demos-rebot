# HandUMI 업데이트, 2026-10-12 → 2026-10-20

[English](UPDATE_2026-10-20.md)

이 문서는 v5 기술 리포트(2026-10-12) 이후 HandUMI 작업에서 바뀐 내용을 정리한 것입니다. 리포트 자체는 변경되지
않았으며, 여기 적힌 내용은 아직 리포트에 반영되지 않았습니다. HandUMI는 여전히 우리 설계가 아니라 **BrikHMP18의 설계**
([murobotics-ai/handumi-hw](https://github.com/murobotics-ai/handumi-hw))입니다. README를 참고하세요.

laundry 프로젝트를 위해 태스크가 큐브 쌓기에서 **티셔츠 펴기("Flatten and align the T-shirt.")**로 바뀌었습니다.
아래 내용은 모두 오프라인 데이터 작업 또는 벤치/텔레옵 테스트입니다. **이 데이터로 학습한 정책은 아직 로봇에서
평가된 적이 없고, UMI→로봇 리플레이도 아직 실행되지 않았습니다.**

## 2. 손목 영상으로부터 그리퍼 개폐 추정

서보를 제거했기 때문에 사용 가능한 UMIalign 테이크 85개 중 74개에는 `/gripper` 토픽이 없습니다. 대신 손목 카메라
영상의 빨간 테이프로 jaw 개구량을 측정합니다. 데이터셋 라벨에는 학습된 모델이 전혀 관여하지 않습니다.

파이프라인:

1. `pipeline/umi_laundry/umi_fusion_scripts/jaw_redx.py` — 빨강 마스크 = `R − max(G,B) > 35` 및 `R > 90` (hue 게이트는
   얇고 압축된 X 획을 놓쳤음). jaw가 닫히면 두 테이프가 하나의 blob으로 합쳐지므로, 빨간 픽셀을 이미지 중앙 열에서
   나누고 왼쪽 절반과 오른쪽 절반 centroid 사이의 거리를 개구량으로 씁니다(1920 폭 기준 px). 서보와 겹치는
   테이크에서 서보 대비: corr 0.93, 열림/닫힘 일치율 97.8 %.
2. `jaw_track.py` (v2) → `<episode>/derived/jaw/jaw_{side}.npz`, 손목 프레임당 값 하나. 각 컴포넌트를 중앙에서
   나누고, 깨끗한 프레임에서 side별 기준값(끝점 높이, 테이프 면적)을 잡습니다. 후보는 느슨한 높이 밴드(±320 px)와
   면적 범위 안에 있어야 하며, 후보가 여러 개면 시간적 연속성으로 고릅니다. `--reselect`는 영상을 디코딩하지 않고
   선택 단계만 다시 실행합니다. 한 번 실행에서 154개 side 전체가 Mac 프로세스 7개로 약 6분 걸립니다.
3. `cart20/ego_cart20/sources/jaw_visual.py` — 이진 라벨: 풀링한 히스토그램(188k 프레임)은 쌍봉 분포로,
   닫힘 110–150 px, 열림 280–450 px. 히스테리시스 **닫힘 ≤ 200 px / 열림 ≥ 260 px**, > 650 px = 이상치(NaN), 0.5 s 이하의
   NaN 구간은 이웃 값으로 채우고, 더 긴 구간은 유지하되 invalid로 표시. 1 = 열림.
4. `sources/hfold_export.py`는 에피소드에 서보 샘플이 있으면 서보를 사용하고(방향은 해당 에피소드의 그리퍼
   캘리브레이션에서 읽음), 없으면 시각 소스를 사용합니다. `{side}_gripper_valid`를 기록합니다.

검증: valid 비율 중앙값 1.0, 열림 프레임 18–21 %, side당 전환 약 11회, 랜덤 프레임 16/16 정답.
10-15 수정(≥ 0.5·a_ref 후보가 작은 점보다 우선)으로 프레임의 1.28 %가 바뀌었고, 모두 닫힘→열림이었으며 12/12 확인.
valid가 낮은 side(< 0.95): 144936 ep2/7/9/10 L (~0.75, X 마크 시절), 160900 ep08 R 0.79, 112920 ep13 L 0.77.

발견한 함정: 다른 유닛의 테이프가 끝점보다 ~430 px 위에서 화면에 들어옴. 책상 위 점들이 작은 X 마크용 크기 테스트를
통과함. 한쪽 테이프가 가려지면 v1은 빈 절반의 점들을 평균냈음. **손목 카메라가 jaw에 강체로 고정되어 있지 않음**
(한 테이크 안에서 끝점이 y = 437과 y = 635), 따라서 좁은 밴드나 호(arc) 피팅은 쓸 수 없습니다.

텔레옵 변형(라벨에는 사용하지 않음): 라이브 텔레옵은 같은 테이프를 처음에는 픽셀 규칙으로, 이후에는 마스킹된 jaw ROI에
대해 파인튜닝한 ResNet18 분류기로 읽었습니다(`experimental/visual_teleop/tools/jaw_capture.py`, `jaw_finetune.py`;
라이브 정확도 0.96 / 카메라 마운트 변경 후 0.92). `.pt` 가중치는 저장소에 없습니다.

## 3. UMIalign 수집

- 수집기 모드 `--dataset UMIpilot|UMI100|UMIalign`; UMIalign = 접기의 Stage 1만 단독으로 수행, 프롬프트 "Flatten and align the T-shirt.", finish-early가 있는 60 s AUTO 윈도우 (`collection/configs/handumi/tasks.yaml`).
- AUTO 루프 추가 사항: finish-early 이벤트, 짧은 음성 안내, 2 s마다 `device_status.json`, `session_log.txt`.
- **끝부분 트림:** 끝에서 운영자가 SPACE를 누르러 손을 뻗는 구간을 `<episode>/trim.json` +
  `trim_manifest.json`으로 비파괴적으로 잘라냅니다(`space_trim_points.py`, 자이로 프로파일 onset − 0.25 s, 1.2–3.3 s 제거).
  `hfold_export`와 smoother가 이를 반영합니다.
- **Raw QA:** `raw_qa.py` (빈 테이크, 빨간 X 유무), `detect_wrist_flip.py` (손목 카메라 회전, jaw 미검출).
  제외된 에피소드는 `episode_meta`와 `<session>/excluded_episodes.json`에 `exclude_from_training`이 기록됩니다.
- 학습에 사용한 세션: `UMIalign_20261013_160900` (30), `20261014_112920` (33), `20261015_112743` (50개 유지;
  eps 3/13/18/41 제외 후 46). 접기 테이크(UMIpilot/UMI100)는 **사용하지 않습니다**.
- IMU 스트리밍 중 Orbbec depth가 4–10 s 멈추던 현상은 Mac USB 스택 상태 문제였고, 재부팅으로 해결되었습니다
  (`collection/tools/orbbec_{alone,combo}_test.py`).

## 4. 포즈 파이프라인 (world 프레임에서의 손목 TCP)

`pipeline/umi_laundry/` 및 `cart20/ego_cart20/umi_fusion/`.

1. **MASt3R-SLAM restart_v1** (`umi_fusion_scripts/m3_runner/run_perframe_restart.py`): RELOC 프레임 15개 후 재시작.
   valid 비율 11–36 % → 87–99 %. side당 VRAM이 ~3 GB 누수되므로 태그마다 새 프로세스 하나를 씁니다. 세션 MASt3R는
   임대한 4090(Vast.ai, RunPod)에서도 실행했으며, 결과는 md5 검증 후 회사 스토리지(5090 NFS, 휴대용 SSD)로 옮겼습니다.
   클라우드 번들 스크립트는 저장소에 없습니다(호스트 주소, 계정 관련 정보).
2. **Orbbec body tracking** (`orbbec_tracking/handumi_body_track.py --profile laundry_v1`, 테이블 위 높이)과
   canonical tracker (`handumi_canonical_track.py`, 파라미터 고정). held-out recall 0.70–0.73.
3. **Smoother** (`ego_cart20/umi_fusion/run_smoother.py`): Orbbec 위치 앵커 + IMU 중력/자이로 + MASt3R 단기 구간
   모션. MASt3R가 수 초 만에 드리프트하기 때문에 필요합니다(세그먼트당 Sim3 잔차 p50 69 mm vs 2 s 윈도우에서 9 mm;
   20 s에서 tilt 오차 최대 24°).
4. **잘못된 TCP 라벨의 근본 원인(10-15), Orbbec에 보이는 jaw 테이프 대비 절대 검사로 발견**
   (`orbbec_tag_check.py`). smoother 자체 QA로는 보이지 않았음:
   - 오래된 camera↔IMU 회전: 오른쪽 17.5°, 왼쪽 23.7° 어긋남 → `camera_imu_Rcb_data_v003`;
   - 자유 변수였던 camera→body 레버가 유닛에서 20–35 cm 벗어난 값으로 수렴 → jaw 테이프 끝점에서 얻은 고정 prior
     (`tips_v001`, σ = 1e-4);
   - 어두운 소매가 Orbbec 앵커를 가로챔 → AprilTag 게이트 (`orbbec_tag_gate.py`, 태그에서 120 mm 넘게 떨어진 앵커 제거).
   플래그: `--rcb data_v003 --rc-prior tips_v001 --sigma-rc 0.0001 --tag-gate` → `derived/umi_fusion_rcb3gate`.
   TCP↔jaw 테이프 p50: 수정 전 25–36 cm → 수정 후 세션별 38–59 mm; p90은 여전히 15–30 cm.
5. 엄격한 제외 기준(ep-side 중앙값 > 80 mm, 게이트 > 30 %, 샘플 < 10개) → **65 에피소드** (160900 27 + 112920 17 +
   112743 21) = 데이터셋 `umi_unfold65c922flange_rcb3` (train 56 eps / val 9).
6. 세션별 지표 테이블: `drivers/umialign_metrics.py --session <dir>`.

학습 현황: 63/109 에피소드 파인튜닝은 수정 전 포즈로 학습된 것이므로 베이스라인으로만 씁니다. 수정된
65 에피소드 파인튜닝(Soft-Fold pretrain 300k에서 시작한 Multi-Task DiT)은 **10-16에 ~11k 스텝에서 사용자가 중단**했으며,
결과는 없습니다.

## 5. UMI → 로봇: robotization, TCP 캘리브레이션, 리플레이 parity

**Robotization** (`cart20/ego_cart20/robotize/`): 사람 TCP 궤적 → reBot base 프레임. 시작 TCP들 사이 테이블
위에 태스크 프레임을 둠; 모드 A/B와 C(양팔에 공통인 IK line-search alpha 하나, 불가능하면 HOLD); IK 잔차, 관절 한계,
테이블, 작업공간, 양팔 간 거리, 관절 스텝을 검사. 학습 에피소드 10개에 대한 첫 수치(모드 C, time scale 2):
IK-ok p50 0.79, 진폭 비율 ~0.81, L↔R 상대 오차 p50 ~50 mm. 데이터셋은 아직 만들지 않았습니다.

**10-16 리드 결정:** 스테레오 카메라 제외; 목표는 UMI로 수집한 모션이 reBot에서 동일하게 리플레이되는 것.

**UMI TCP 캘리브레이션 (10-20 완료)** (`pipeline/umi_robot_parity/`): 고정 global Orbbec + 3-태그 리그.
멀티 코너 리그 PnP(보이는 모든 태그 코너, SQPNP + LM)로 정지 상태 회전 지터를 1.78° → 0.39°로 줄였습니다. TCP는 pivot
대신 **보드 코너 터치**로 피팅합니다(`tag_rig_touch_tcp.py`, 50 mm AprilGrid id 300–311, 안정 구간 hold) (pivot은 왼쪽
유닛에서 ~3 cm 어긋났음). 결과는 `configs/umi_tag_rig_v001.json` (`tcp_in_rig_m`): 오른쪽
(10.12, 5.54, −4.29) cm, 왼쪽 (−11.17, 5.67, −4.56) cm; 정적 절대 오차 1–4 mm, leave-one-corner-out 1.8–4.8 mm.
상대 회전에 대한 hand-eye로 구한 IMU↔리그 회전: 왼쪽 rotz(−89.5°) +10 ms, 오른쪽 rotz(+89.8°) +15 ms. 정적 hold에서는
IMU 융합이 아무런 이득을 주지 않습니다.

**리플레이 parity 도구 (구축 완료, 로봇에서는 미실행; 로봇이 설치되지 않았음):** `robot_cam_poses.py` (READY 주변 포즈 32개,
기본값 dry-run), `robot_cam_solve.py` (T_base_cam + T_flange_tag, 재투영 + depth 잔차, k-fold;
합성 데이터 PASS), `umi_tcp_traj.py`, `umi_replay.py`, `replay_parity.py` (A = UMI 측정, B = 로봇 명령,
C = 정규화된 경로 진행도 기준 로봇 실행; 게이트: 진폭 비율 0.9–1.1, leak < 10 %, 끝점 < 20 mm,
RMSE < 20 mm, p95 < 30 mm, 반복 std < 10 mm). 10-20에 찍은 UMI 단독 6방향 테이크는 사용 가능; 사람이 스트로크당
20–35 cm 움직였으므로 긴 스트로크는 리플레이 한계에 걸려 거부될 수 있습니다.

**Kalibr** (`pipeline/umi_robot_parity/kalibr/run_kalibr.sh`): 명령 하나로 ROS1 bag export → 4090의 Kalibr docker.
인쇄한 AprilGrid에는 `patch_kalibr.py`가 필요합니다(1-bit border, 태그 180° 회전). 패치가 없으면 잔차가 ~70 px, 있으면
0.5 px.

## 6. 텔레옵 장치로서의 UMI (실험적, 부정적 결과도 기록)

`experimental/visual_teleop/` + `experimental/scripts/umi_teleop_eval/`. 라이브 텔레옵을 위해 시도한 손목 포즈 소스:

| 소스 | 결과 |
|---|---|
| 손목 카메라 DPVO | NO-GO: 30 s까지 회전 드리프트 40–80°, 스케일이 0.03–1.25 사이에서 흔들림 (흰 테이블 + 천이 시야를 채움) |
| 방을 향한 fisheye의 mono VIO (OpenVINS / Basalt / ORB-SLAM3) | NO-GO (지터 p90 76–82 mm, 가짜 병진 27–92 cm) |
| 스테레오 VIO (fisheye 2대 + XIAO) | 10-16 첫 실로봇 텔레옵 (30 Hz로 81 s, IK 거부 0, 그리퍼가 테이프를 따라감), 그러나 보드 GT ATE 18.5 cm이고 카메라 브래킷이 미끄러짐; 10-16 제외 |
| 고정 Orbbec + 태그 + IMU | 데이터용으로 유지한 경로 (5절) |

교훈: 트래킹 카메라는 정적이고 텍스처가 있는 장면을 봐야 하는데, 천을 조작하는 동안의 손목 시야는 그렇지 않습니다.
